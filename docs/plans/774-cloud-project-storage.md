# Private complete-project cloud storage

Issue: [#774](https://github.com/andeplane/fem-lab/issues/774). Client integration is [#775](https://github.com/andeplane/fem-lab/issues/775); faithful portable retained results are [#779](https://github.com/andeplane/fem-lab/issues/779).

Implement an authenticated repository for complete, opaque project artifacts, including portable results, files and completed outputs supplied by the client. A Model-and-Journal-only file is not a complete retained-result archive. Anonymous projects remain local; account ownership is resolved from verified identity rather than any request account selector.

Use the existing PostgreSQL service for owner/revision metadata, upload reservations, counters, durable cleanup and idempotent receipts. Store fixed 8,000,000-byte chunks plus a final short chunk in a separate private GCS bucket. Validate size and SHA-256 at upload, verify every immutable object generation before commit, and bind downloads to a current project revision. New project IDs and all object keys are generated by the service.

Enforce decimal plan quotas: Free 100,000,000; Plus 2,000,000,000; Pro 10,000,000,000; Studio 50,000,000,000 bytes. Plan comes from active paid grants, independently of remaining AI tokens or free-AI eligibility. Reserve the positive replacement size delta while separately bounding full temporary/cleanup exposure. Downgrade retains reads/deletes; current quota is checked again at commit.

Keep global physical exposure bounded initially to 100,000,000,000 bytes, configurable by the operator. Independently bound account/global project, upload, chunk and rate metadata, including deletion markers and failed cleanup. Fixed chunk topology and one bulk SQL insert prevent tiny-chunk metadata amplification. Expire incomplete reservations after 30 minutes and retain failed-cleanup exposure until deletion is confirmed. The five-minute writer lease covers the HTTP receive deadline and bounded GCS operation.

Account deletion freezes admissions before purging cloud objects and metadata; identity deletion cannot finish while project cleanup remains pending. The account export contains a cloud project index, with complete binary artifacts available through authenticated project downloads. No provider or payment operation is part of project storage.

Infrastructure is covered by the linked [private bucket plan](./774-project-storage-infrastructure.md). See [ADR 0043](../adr/0043-private-cloud-project-artifacts.md) and the [public API guide](../guide/cloud-project-api.md).

Verification: real PostgreSQL tests cover cross-account denial, authenticating before raw-body reads, concurrent byte/metadata ceilings, fixed topology, exact binary round trips, stale revisions, idempotent replay, expiry, missing/corrupt objects, downgrade, pending cleanup and account deletion. Adapter tests verify GCS generation preconditions and binary integrity. Run full service/registry coverage, build/typecheck, documentation checks and existing infrastructure guards before review/deployment. Root coordinates staging-first service release and real owned-artifact acceptance without creating production identities or credit/payment activity.

Rollback: retain migration 011, private buckets and project-aware recovery jobs after the first cloud write. Rolling API traffic back must not roll recovery back to a pre-cloud image: old recovery can finalize identity deletion without purging cloud objects. Never down-migrate live project tables or reuse the expiring export bucket. Record deployed acceptance separately from local tests.
