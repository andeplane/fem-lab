# Account-owned browser project sync

Issue: [#775](https://github.com/andeplane/fem-lab/issues/775). Service API: [#774](https://github.com/andeplane/fem-lab/issues/774). Portable solved-state boundary: [#779](https://github.com/andeplane/fem-lab/issues/779).

Authenticated projects save first to a browser cache captured for that account, then queue a cloud revision automatically. Anonymous projects remain browser-local. Uploading an existing anonymous project is an explicit copy into the signed-in account; it never transfers or removes its anonymous original. No account adopts another account's cache or in-flight operation, including an A → B → A identity cycle.

The artifact contains the portable engine document and retained solved states from #779, metadata, original inputs actually imported, and completed output file bytes. It does not scan or upload unrelated selected-folder files. Model-file exports retain the existing `femlab/1` format; cloud projects use a separate bounded container. Legacy journal-only browser projects remain openable; only available data can be recovered from those old saves.

Every local repository and autosave-history adapter captures its owner before asynchronous work. A project binding also captures generation/session/version. Account changes hide old private projects, Model, Result canvases, Assistant/folder context and retained files immediately; old writes may finish only in their captured namespace. Publication of network lists/downloads/commits checks the full authentication epoch as well as the UID. A new account starts a fresh engine session; no old producer may act on it.

Cloud transport is injected and typed. The service accepts an opaque chunk manifest, reserves quota, verifies uploaded chunk lengths/hashes and commits against a base revision. Downloads pin the same revision across every chunk. The client persists its base revision and dirty generation before network work, retries resumable uploads with the same idempotency key/body, and never clears a newer local save after an older upload completes. A conflict preserves both local work and the current remote revision; recovery requires choosing a separate copy or explicitly restoring the remote version. Deletion retains a tombstone and cannot be undone by a delayed save.

The UI distinguishes browser-local, pending, synced, offline, conflict and quota/error states. Storage usage and limits are server-authoritative; proposed decimal quotas are Free 100 MB, Plus 2 GB, Pro 10 GB and Studio 50 GB. A full quota or failed network does not discard the local cache or disable local export. Only current cloud revisions count as retained project history; browser revision recovery is separate.

Verification covers namespace injection and account switches, captured delayed operations, full binary/text artifact round-trips, solved-state provenance, corrupt/truncated/bounded containers, quota rejection, idempotent retries, remote revision conflicts, offline edits/reconnection and another-browser restore. Browser fixtures use local typed fake APIs; production smoke uses only explicitly owned artifacts, no fabricated accounts, model calls or payments.
