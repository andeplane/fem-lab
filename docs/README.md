# FEM Lab documentation

FEM Lab has a Rust finite-element engine, a Chromium browser app, a native CLI, and a Node MCP
host. The browser runs the engine as WebAssembly. Commands build the Model; the engine Journal
records them so the analysis can be replayed. Queries inspect the current state and Results.

## Start here

- [Getting started](GETTING-STARTED.md): build a checkout, open a cantilever, solve and inspect it.
- [Engine Command and Query reference](COMMANDS.md): generated arguments, constraints and schema definitions.
- [Guided tutorials](TUTORIALS.md): the tutorial index, topics and corresponding model files.
- [Example catalogue](EXAMPLES.md): runnable Journals and their reference calculations.
- [Benchmark catalogue](BENCHMARKS.md): analytical and published verification cases, convergence studies and measured status.
- [MCP setup](../packages/mcp/README.md): build the local tool server and connect an editor.
- [Contributing](../CONTRIBUTING.md): issue ownership, worktrees, verification and PR requirements.

## Understand the system

[CONTEXT.md](../CONTEXT.md) defines Model, Journal, Command, Query, Result and Host.
[Architecture decisions](adr/) explain the Rust/TypeScript boundary, numerical precision,
units, extension points and browser support. [The implementation plan](PLAN.md) distinguishes
planned capabilities from delivered ones. A planned benchmark or feature is not a supported
capability merely because it appears in a design document.

The engine reference is regenerated by `npm run codegen`; `npm run codegen:check` fails if it
is stale. The browser also has host Commands for camera, selection, panels and files. Inspect
`fem.registry.list()` in its console to see the combined registry available in that host.
