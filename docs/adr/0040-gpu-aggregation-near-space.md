# A fixed symmetric GPU aggregation cycle carries explicit reduced near modes

The existing Jacobi scaling preserves f64 refinement but leaves the large bending system
ill-conditioned. Bounded exported operators (216, 1200 and 5832 rows) support a vector
smoothed-aggregation cycle with a degree-four Chebyshev smoother. These CPU algorithm-selection
experiments are neither GPU correctness evidence nor a performance claim. The source below is
a provisional implementation pending actual compiler, software-GPU, 66k and real-device D5 gates.
The existing f64 tolerances and arithmetic-floor policy remain unchanged.

## Boundary

Keep the registry and Journal unchanged. Solver internals are not a plugin extension point
(ADR0010). Preserve generic solve APIs as wrappers without optional metadata. A private owned
NearSpace carries node_of_row and unscaled reduced displacement-mode columns. Procedures
pass a private borrowed PhysicalSpace descriptor (mesh, idealisation, retained DOFs and
stride); only GPU preparation materializes its admitted columns. Procedures retain geometry
and constraints, and CPU solvers never allocate those columns.

Static procedures reuse the idealisation-aware rigid_basis already used by well-posedness
checks. The reduced row i belongs to original node red.free[i]/dofs_per_node; its candidate
value is R[red.free[i]]. Never infer components from reduced row modulo, and never use the
force pullback T^T on displacement candidates. In H=T E_free, retained rows are identity,
so the legal homogeneous correction generated by a reduced candidate is H R_free. Prescribed
values and MPC/contact offsets do not belong to a correction. Restriction through cyclic or
active contact constraints produces heuristic near modes, not necessarily exact rigid modes.
Rebuild this handoff after each changed active-set/free-row map. Only allocate metadata when
the resolved solver uses a Fine GPU aggregation root, and admit its at-most-six full and
reduced mode columns first. Roots at or below the shared 96-row coarse threshold directly
factor their matrix and do not consume candidate columns.

For A_s=S K S and physical displacement u=S y, scaled candidates are S^-1 R_free. The
setup may augment an algebraic constant candidate to cover scalar or otherwise unrepresented
rows; this does not claim it is a physical rigid mode. Rank-reveal each aggregate locally in
fixed column/row order. Use at most sixteen node groups per greedy aggregate, raw block-Frobenius edge strengths,
ascending node/group tie breaks and two fixed Gram-Schmidt passes with relative rank threshold
1e-10. Propagate Q^T B to the next level without appending a fresh constant there. Repeated
null candidates are removed by local rank, not by altering the physical constraints.
Record actual coarsening and reject exhausted resource bounds.

The fixed aggregate size was increased from eight to sixteen after the actual 780k
hierarchy exhausted the unchanged cumulative setup allowance. This trades a smaller
coarse approximation for less hierarchy fill and potentially more Krylov iterations;
it changes neither the physical operator nor the declared near modes. A controlled
CPU prototype using the same raw-strength 216/1200/5832-row exports reduced the largest
hierarchy's total operator entries from 912601 to 585457 and prolongation entries
from 347721 to 215589, while rounded-system iterations increased from 79 to 106.
Those experiments select a candidate only: SciPy traversal/storage is not the Rust
admission ledger or GPU/physical acceptance. The original 66k and 780k scientific
oracles must still pass; prior iteration counts are observations, not requirements.
All other interpolation, QR, smoothing, factorization and resource policies remain.
The finiteness proof's conservative eight-group contraction still holds because the
fixed sixteen-group policy contracts at least as strongly.

## Algebra

Use one fixed V-cycle as M^-1 during a PCG solve. Setup and Galerkin products run in f64;
fine/coarse operators, restriction/prolongation, smoothers and vectors execute in f32 on the
injected GPU. Store CSR prolongation and its actual transpose so both directions gather;
no scatter atomics. The tentative interpolation T comes from aggregate-local orthogonal
candidate columns. Smooth it with P=(I-omega D^-1 A)T. The initial safe omega=.8/L uses an
absolute-row-sum upper bound L>=rho(D^-1 A); its factor stays nonsingular for SPD A.

Pre/post smoothing must be an explicitly matched fixed polynomial. Use four Chebyshev roots over [.1 L,L] in the forward pre-smoothing sequence and reverse
them for post-smoothing. L bounds both the ideal f64 row sum and the exact uploaded f32
row sum multiplied by its uploaded normal positive inverse diagonal; upward-rounded f64
sums retain the upper bound. This gives a fixed polynomial, rather than estimating a new
smoother or stopping criterion during an inner solve. Never
use a tolerance-driven coarse CG inside standard PCG. Coarsest factorisation is bounded f64
Cholesky; upload the inverse triangular factor C=L^-1 and apply C followed by its stored
transpose, giving B_c=C^T C. This avoids rounding an explicit inverse into an indefinite
preconditioner. Fail honestly if the coarse factorisation cannot be built.

PCG uses z=M^-1 r and rho=r dot z; retain a separate r dot r for convergence. The original
f64 residual and existing tolerances/floor decide physical success. A device halt distinguishes
convergence, budget exhaustion, nonpositive uploaded curvature and nonfinite scalars, with
actual updates separate from encoded batches. Finite partial progress can still be assessed
by f64 refinement; a zero-update curvature failure or nonfinite solve is structured
solve.stalled, without declaring the original f64 operator indefinite or silently falling
back to CPU. No SPD preconditioner can repair an indefinite rounded operator.

## Bounds and proof

One pure preparation boundary receives explicit limits and admits fine copies/chunk spans,
physical columns and the hierarchy before GPU buffers exist. It returns immutable admitted
input. The complete required CG/aggregation pipeline bundle compiles before infallible
buffer upload; failed preparation or compilation never starts an alternative solver.
Chunk spans reserve exactly their charged worst-case capacity instead of geometric growth.

Admission precedes allocation: mode columns, aggregation scratch, levels/coarse size,
prolongation and Galerkin symbolic fill, construction payload allowances and individual device buffers. The setup allowance
charges cumulative requested Vec storage, including old/new growth overlap; live ordered-map
entries reserve conservative storage until their maps are released. This is deliberately not
an allocator/RSS/peak-memory estimator. Sparse product rows use four fixed partitions: first
admit symbolic map envelopes, then count exact fill, then admit one final CSR and four
borrowed output-span headers before repeating identical row arithmetic in parallel. Prefix
offsets split the final index/value arrays into disjoint mutable slices; each span borrows
only its partition's row offsets plus sentinel. Empty partitions have one sentinel and no
writable entries. This removes the former owned blocks and merged copy without changing
the cumulative allowance, arithmetic or fixed partition order. Final arrays are initialized
before indexed writes, trading that initialization bandwidth for fewer allocations and no
merge copy. Setup remains independent of pool size. The bounded coarsest operator has at
most 96 rows.

AP becomes dead after raw=PT*AP completes. Its owned buffers may then supply the local
transpose(raw) output when their originally requested lengths fit. Eligibility never uses
allocator capacity; all old charges remain, and a miss admits a complete fresh replacement
before allocation drops the old buffer. The cursor remains separate and newly charged.
This avoids a new request without changing the cumulative allowance or extending AP's
existing lifetime across recursion. It changes neither entry counters nor transpose order.

After a symmetry fill joins, its raw and transposed inputs are dead. Move these two
owners to the immediate child as fixed-role output donors: raw supplies the child's
raw product and transposed supplies its symmetric operator. AP remains fresh, and the
local AP-to-transpose path above remains unchanged. No pool or role search exists.
Each array independently reuses only an initialized, admitted logical prefix; all missing
full replacements and output-span metadata are admitted together before mutation. Counts,
entry caps, four partitions and numerical traversal remain unchanged. A coarse leaf drops
unused donors before factor construction, without retiring any cumulative charge.

This extends two buffers' live ranges across the next setup level. Truncation preserves
original allocations, so logical lengths prove eligibility, not physical storage size.
In particular an AP-backed transpose can become a retained symmetric operator and keep its
larger allocation throughout deeper setup and upload. This trade-off removes real fresh
requests under the same cumulative contract; it does not establish an RSS bound. Device
runs require separate host resource admission and actual peak-memory guards.

The initial private setup/device payload caps differ between native and wasm32 hosts; they
remain experimental construction guards until measured on 66k. The near-space handoff has a
separate 256 MiB construction bound. Exact diagonal systems skip both metadata and hierarchy
and retain the exact identity preconditioner. This is an algebraic specialization, never a
fallback after a hierarchy error. Each actual GPU buffer also checks the injected device's
min(maxBufferSize,maxStorageBufferBindingSize), including CSR row sentinels, scalar scratch,
vector workspaces and chunk uniforms, before creation. The cost Query remains an assembly
lower bound and explicitly excludes hierarchy/setup/device copies. A small estimate does not
establish browser memory feasibility or supersede runtime admission. A local hard bound is distinct from host memory availability. Do not turn a missing
budget into an undocumented plain-CG fallback. Independently check Poisson sine eigenmodes,
preconditioner symmetry/linearity/positive energy, elastic affine/Poisson patches, material
jumps and disconnected/rank-deficient modes. Preserve one/N-thread setup bits and repeat
actual GPU results. Software adapters prove correctness, never performance. D5's 780300-row
harness must assert finite physical/residual/reference results with the declared B1 tolerance,
while retaining the 66k sibling and actual original imported-reference checks. The 66k
sibling is now exercised through the public procedure with physical reduced candidates and
keeps its 1e-8 displacement comparison to direct factorisation. D5 uses B1's unchanged 2% tip
deflection reference, f64 relative residual below 1e-8 (the existing 100-times-floor policy),
finite displacements and global force/moment residuals below .001 N/.001 N m for its 1 kN
load. No massive direct factorisation, tolerance change or timing assertion is introduced.
